### 2.1 서비스 입구 (Workspace 재정의)

지금 WORK는 두 가지가 섞여 있다.

1. **이 사이트의 서비스 입구** — Planner's "내 플래너"(→ /planners/app), WIO "Orbi 시작하기", SmarComm "워크스페이스". 사이트(소개)와 별개로 **로그인 후 쓰는 앱 화면**이 있는 브랜드에만 필요하다.
2. **내가 쓰는 다른 브랜드 목록** — `members.affiliations` 기반 드롭다운. 헌법 원칙 7(유니버스는 강조하지 않는다)과 어긋나고, 브랜드 가입의 SSOT도 `affiliations`가 아니라 `member_brand_joins`다.

**제안**
- 바에는 **1번만** 남긴다. 서비스형 브랜드(앱 화면 보유)만 버튼 1개, 문구는 브랜드가 정한다 (`serviceEntry: { label, href }`).
  - 이용자: "내 플래너" → 앱 · 미이용자(이 브랜드 첫 진입): 같은 버튼 → `BrandJoinGate`(브랜드 약관 동의) → 앱. 버튼을 둘로 나누지 않는다
  - 커뮤니티·콘텐츠 브랜드(Badak·MADLeague·RooK 등)는 서비스 입구 없음 — 마이페이지가 그 역할
- 2번은 계정 메뉴 안 **"이용 중인 다른 서비스"**로 옮기고 원천을 `member_brand_joins`로 바꾼다.

### 2.2 아바타 — "유니버스 계정"과 "이 사이트의 나"의 조합

고민: 아바타 하나가 ① Ten:One 계정(이름·사진·보안·동의·탈퇴) ② 이 사이트 안의 나(활동·특화 정보) 두 가지를 다 대표해야 한다.

**제안: 아바타는 바로 이동하지 않고 계정 메뉴를 연다** (Google "Google 계정 관리" 패턴)

```
┌──────────────────────────────┐
│ (사진) 이름                    │  ← 메뉴 안에서만 이름 표시 (바에는 사진만, 현 규칙 유지)
│        email                   │
├──────────────────────────────┤
│ 마이페이지                     │  ← 이 사이트의 나: /{brand}/my (MyProfileCard + 브랜드 활동)
│ 내 공개 프로필                 │  ← handle 있을 때만: /@handle
├──────────────────────────────┤
│ Ten:One 계정 관리              │  ← /profile (공통 프로필·보안·동의·탈퇴) — 모든 도메인에서 열림
│ 이용 중인 다른 서비스 ›        │  ← member_brand_joins 기준, 원칙 7에 맞게 메뉴 깊숙이
│ 인트라                         │  ← 직원만 (member_roles 기준)
├──────────────────────────────┤
│ 로그아웃                       │
└──────────────────────────────┘
```

- 이렇게 하면 "마이페이지만 있어서 로그아웃 못 하는" 문제가 구조적으로 사라진다 (메뉴 맨 아래 고정)
- **ADMIN 링크는 바에서 없앤다** → 계정 메뉴의 "인트라"(직원만). 브랜드별 관리 화면은 인트라에만 둔다 (§1.9)
- ⚠️ 현행 규칙 변경: §1.9.2 "로그아웃은 바에 텍스트로" → "계정 메뉴 맨 아래". 아바타 클릭이 곧 로그아웃은 여전히 금지

### 2.3 알림

- 계정 단위 하나 (`/api/notifications`, 생성 `lib/notify.ts`). 본인에게만 보이므로 다른 브랜드 알림이 섞여도 교차 노출(데이터 계약 4)에 해당하지 않는다
- 알림마다 브랜드 표시, 이 사이트 알림을 위에. 배지가 보여야 하므로 **모바일에서도 헤더에** 둔다

### 2.4 로그인 / 로그아웃

- 로그인: LoginModal (현재 페이지 위, 복귀 §1.2.1) · 가입: SignupConsent · 브랜드 첫 진입: BrandJoinGate
- 로그아웃: 계정 메뉴 맨 아래. 로그아웃 후 현재 페이지에 머문다 (보호 페이지면 LoginRequired가 처리)

### 2.5 핸들 페이지 (공개 프로필)

| 주소 | 내용 | 원천 |
|---|---|---|
| `/@handle` → `/profile/{handle}` (전 도메인) | 유니버스 공개 프로필 — 본인이 공개한 공통 필드만 | `get_public_profile` RPC |
| `myverse.kr/{handle}` | MyVerse 공개 페이지 | `myverse_public_handles` |
| `/jakka/{handle}` · `/montz/{handle}` | 그 브랜드의 창작자 포트폴리오 | 브랜드 테이블 |

- 핸들은 `members.handle` 하나. 유니버스 프로필에 브랜드 활동을 띄우려면 그 브랜드 활동에 대한 **별도 동의** (데이터 계약 4)
- 계정 메뉴에 "내 공개 프로필" 1줄 (handle 있을 때만)
- 🐞 MoNTZ `[handle]` 본인 판정이 이메일 앞부분·이름 문자열 비교 (`app/(MoNTZ)/montz/[handle]/page.tsx:80`) → `members.auth_id` 기준으로 (데이터 계약 1)

## 3. 헤더 3유형 — 예외를 "유형"으로 흡수

| 유형 | 대상 | 우상단 구성 |
|---|---|---|
| **사이트형** | 브랜드 웹사이트 전부 (Badak·HeRo·MADLeague·RooK·Planner's 사이트·Mindle·SmarComm·WIO·YouInOne 소개 사이트…) | [주 행동 버튼 1개, 선택] + 사이트 도구 + 계정 묶음 |
| **앱형** | 로그인 후 쓰는 화면: Planner's 앱 · MyVerse 앱 · WIO 앱(/wio/app) · SmarComm 대시보드 · 인트라 | 앱 도구(검색·도움말·설정) + 알림 + 계정 메뉴. About·공유 없음. 계정 메뉴에 "사이트로" 1줄 |
| **피드형** | Jakka · MoNTZ (인스타형 사이드바) | 같은 부품을 사이드바 하단에 세로 배치. 모바일은 사이트형과 동일 |

- **주 행동 버튼(CTA) 슬롯 1개**: 브랜드 핵심 행동 하나만 (예: YouInOne "Members & Alliance", WIO "Orbi 시작하기"). 서비스 입구와 같으면 하나로 합친다
- **메뉴는 메뉴 자리에**: SmarComm의 서비스·블로그·요금제는 사이트 메뉴다 → 메인 메뉴로 (`lib/brand-site-menus.ts`). 우상단에 메뉴를 붙이지 않는다

### 모바일 (모든 유형 공통)

```
헤더     [알림] [아바타 | 로그인] [☰]
서랍     메뉴 → (사이트 도구: About·검색·공유) → 맨 아래: 비로그인 = 로그인·가입
아바타   → 계정 메뉴를 시트(아래에서 올라오는 패널)로
```
- 서랍 하단(footer)을 브랜드가 손으로 쓰지 않는다 — `UniverseMobileMenu`가 자동으로 그린다

## 4. 현황 진단 (2026-10-14 조사)

### 4.1 공통
- 모든 사이트형 헤더가 바를 `hidden md:flex`/`lg:flex`로 숨기고 모바일 서랍 하단을 손으로 만든다 → **모바일에서 알림·검색·공유·로그아웃이 사라짐**. 로그아웃 있는 곳은 TenOne뿐
- 바의 ADMIN 판정 `isAdmin = role==='Admin' || accountType==='staff' || adminEmails` — 본인 수정 가능 컬럼·이메일로 판단 (§1.6 위반, 표시용이지만 제거 대상)

### 4.3 Mindle admin

- `/mindle/admin` = 직원용 운영 화면(수집 데이터·크롤러·기회·콘텐츠 초안)을 **사이트 안에** 둔 것. 브라우저에서 Supabase 직접 조회, 판정은 role/staff/**이메일 3개 하드코딩**(헤더와 페이지에 중복). Mindle CLAUDE.md에도 "임시 관리"로 표기
- 인트라에 이미 `/intra/ums/mindle` (대시보드·회원·수익·콘텐츠·큐·CS)와 Whole See가 있다 — 겹치는 영역 = 콘텐츠·초안
- **제안**: 정의 = "Mindle 운영 = 인트라 UMS › Mindle 하나". `/mindle/admin`의 남은 기능(크롤러 상태·기회)을 인트라로 옮기고 `/mindle/admin`·바의 ADMIN 링크 삭제. 그 전까지라도 이메일 판정 → `member_roles`(직원) 판정으로
