# Brand Gravity 컨설팅 서비스 — 1주 프로세스 설계서

## 핵심 원칙

> **"컨설팅 퍼스트, SaaS가 아니다."**
> 시스템은 컨설턴트를 보조한다. 컨설턴트가 판단하고, 시스템이 데이터를 모은다.
> 단가가 높은 프리미엄 컨설팅이다.

---

## 3단계 상세 — 측정·진단·처방

### 📏 1단계: 측정 (Day 1~2)

> 원 데이터를 모은다. 시스템이 80%, 사람이 20%.

#### 측정 항목

| # | 항목 | 측정 방법 | 담당 |
|---|------|-----------|------|
| M1 | AI 추천 가시성 | 5대 AI 프로빙 (ChatGPT, Claude, Gemini, Perplexity, Copilot) | 시스템 |
| M2 | 검색 가시성 | 네이버·구글 키워드 순위, 검색량 | 시스템 |
| M3 | 소비자 리뷰 데이터 | 쿠팡·네이버·커뮤니티 리뷰 크롤링/시드 | 시스템+사람 |
| M4 | 구매 여정 터치포인트 | 5단계 × AI·검색 동시 프로빙 | 시스템 |
| M5 | 경쟁사 벤치마크 | 경쟁사 3~5개 동일 프로빙 | 시스템 |
| M6 | 브랜드 가치 현황 | 클라이언트 사전 질문서 + 기존 조사 자료 | 사람 |
| M7 | 디지털 발자국 | 공식 사이트, SNS, 위키, 리뷰 사이트 존재 여부 | 시스템+사람 |

### 🔬 2단계: 진단 (Day 3~4)

> 데이터를 해석한다. 시스템이 초안, 컨설턴트가 판단.

#### 진단 항목

| # | 항목 | 진단 내용 | 담당 |
|---|------|-----------|------|
| D1 | 시장 유형 판정 | A(무명)/B(인지-비추천)/C(선점) — 전략 방향 결정 | 시스템→사람 검수 |
| D2 | Gravity Score 산출 | Mention + Coverage + Rank + Context = 100점 | 시스템 |
| D3 | AI 갭 진단 | AI가 왜 추천 안 하는지 — top_gaps | 시스템→사람 해석 |
| D4 | 소스 추적 진단 | 경쟁사는 어떤 소스 덕에 추천되는지 | 시스템 |
| D5 | 카테고리 역풍 진단 | AI가 카테고리 자체를 기피하는지 | 시스템 |
| D6 | **브랜드 인지도 진단** | 소셜 언급량 + AI 인지 + 검색량 종합 | 시스템 |
| D7 | **브랜드 호감도 진단** | 소셜 긍부정 분석 + 연관어 감정 분석 | 시스템 |
| D8 | **브랜드 추천도 진단** | AI 추천률 + 소셜 "추천" 동반출현 빈도 | 시스템 |
| D9 | **브랜드 만족도 진단** | 리뷰 평점 + "재구매" 키워드 + 불만 비율 | 시스템+사람 |
| D10 | 구매 여정 병목 진단 | 5단계 중 어디서 브랜드가 끊기는지 | 시스템→사람 해석 |
| D11 | 경쟁사 비교 진단 | 자사 vs 경쟁사 Gravity Score + 강약점 | 시스템 |

### 💊 3단계: 처방 (Day 5)

> 개선 방안을 제시한다. 컨설턴트가 주도, 시스템이 초안.

#### 처방 항목

| # | 항목 | 처방 내용 | 담당 |
|---|------|-----------|------|
| P1 | **Quick Wins** | 1~2주 내 실행 가능한 즉시 개선 3~5개 | 시스템 초안→사람 |
| P2 | **AEO 콘텐츠 브리프** | AI 추천 최적화 콘텐츠 기획안 5~10개 | 시스템 생성→사람 검수 |
| P3 | **검색 최적화 제안** | SEO 개선 포인트 (메타태그, 구조화 데이터, 키워드) | 사람 |
| P4 | **브랜드 인지도 개선** | 위키피디아 등록, 리뷰 활성화, PR 전략 | 사람 |
| P5 | **브랜드 호감도 개선** | 부정 리뷰 대응, 제품 개선 포인트 | 사람 |
| P6 | **세일즈 액션 플랜** | 매출을 올리기 위한 구체적 실행 계획 | 사람 |
| P7 | **구조화 데이터 제안** | FAQ/Organization JSON-LD 스키마 | 시스템 |
| P8 | **다음 스캔 일정** | 월간/분기 재측정 계획 | 사람 |

## Day별 상세 프로세스 — [시스템] vs [사람]

### Day 1: 킥오프 + 사전 진단

> 클라이언트 만나서 이해하고, 시스템으로 빠르게 시장 위치를 파악한다.

#### 3가지 시장 유형

| 유형 | AI 인지도 | 시장 상태 | 전략 방향 | 예시 |
|------|-----------|-----------|-----------|------|
| **A. 무명 브랜드** | AI가 아예 모름 | 신생·니치 | 인지도 구축 우선 (SEO·콘텐츠 생산) | 춤추는고래 |
| **B. 인지되지만 비추천** | AI가 알지만 추천 안 함 | 경쟁 치열 | 차별화 포인트 강화·소스 확보 | 중소 화장품 |
| **C. 선점 브랜드** | AI가 이미 추천 | 시장 선두 | 방어·모니터링·확장 | 유한킴벌리 |

#### [시스템이 하는 일]
1. **Quick Probe (5분):** 핵심 질문 3~5개만 5대 AI에게 던져서 브랜드 언급 여부 빠르게 체크
2. **경쟁사 인지도 체크:** 경쟁사 3~5개도 동일 질문으로 프로빙 → 시장 전체의 AI 인식 수준 파악
3. **시장 유형 자동 분류:**
   - 자사 언급 0% + 경쟁사도 낮음 → 카테고리 자체가 AI 비가시 (유형 A')
   - 자사 언급 0% + 경쟁사 높음 → 자사만 모름 (유형 A)
   - 자사 언급 낮음 + 경쟁사 높음 → 인지되지만 비추천 (유형 B)
   - 자사 언급 높음 → 선점 (유형 C)
4. **진단 결과에 따라 파이프라인 커스터마이즈:**
   - 유형 A: 콘텐츠 브리프에 "인지도 구축" 카테고리 비중 높임
   - 유형 B: 소스 추적 + 경쟁사 분석 비중 높임
   - 유형 C: 방어 모니터링 + 새 질문 영역 탐색

#### [사람이 하는 일]
1. **클라이언트에게 사전 질문서 발송** (계약 직후)
2. Quick Probe + 검색 진단 결과 해석
3. 소비자 구매 여정 상 터치포인트 파악
4. **클라이언트에게 현실적 기대치 설정:**
   - 유형 A: "AI·검색 모두 부재. 디지털 존재감 구축부터."
   - 유형 B: "검색은 되지만 AI 추천이 안 됨. AEO 최적화 집중."
   - 유형 C: "잘 되고 있음. 방어·모니터링·확장."

#### 🔍 소비자 검색 진단 (Search Visibility Check)

> AI 추천뿐 아니라, 전통적 검색에서의 가시성도 함께 측정한다.
> **"AI에서 추천되는가?"** + **"검색에서 발견되는가?"**를 비교해야 전체 그림이 보인다.

**측정 항목:**

| 채널 | 측정 방법 | 지표 |
|------|-----------|------|
| **네이버 검색** | Naver Search Advisor API / 수동 검색 | 키워드별 자사 순위, 경쟁사 순위, 관련검색어 |
| **구글 검색** | Google Search Console / SerpAPI | 키워드별 순위, 노출 수, CTR |
| **네이버 쇼핑** | Naver Shopping Search API | 상품 검색 순위, 리뷰 수, 평점 |
| **쿠팡** | 수동 검색 | 검색 순위, 리뷰 수, 평점 |

**비교 매트릭스:**
```
               검색 가시성 높음    검색 가시성 낮음
AI 추천 높음   ✅ 최적 상태       ⚠️ AI 의존 (검색 보강)
AI 추천 낮음   ⚠️ 검색만 의존     ❌ 완전 비가시 (긴급)
```

**시스템 출력:** 각 채널별 브랜드·경쟁사 가시성 비교 테이블 → Pre-Scan 리포트에 포함

#### 🛒 소비자 구매 여정 분석 (Purchase Journey Mapping)

> 소비자가 제품을 인지 → 비교 → 구매 → 재구매하는 전체 여정에서
> AI와 검색이 각각 어느 단계에서 영향을 미치는지 매핑한다.

**5단계 구매 여정 모델:**

| 단계 | 소비자 행동 | AI 터치포인트 | 검색 터치포인트 | 측정 |
|------|-----------|--------------|----------------|------|
| **1. 인지** | "이런 게 있나?" | AI에게 카테고리 질문 | 네이버/구글 카테고리 검색 | 카테고리 질문에 브랜드 언급? |
| **2. 탐색** | "어떤 게 좋지?" | AI에게 추천 요청 | "OO 추천" 검색 | 추천 목록에 포함? 순위? |
| **3. 비교** | "A vs B 뭐가 나아?" | AI에게 비교 질문 | "A vs B" 검색 | 비교 시 유리? 불리? |
| **4. 구매 결정** | "이거 사도 될까?" | AI에게 리뷰/평판 질문 | 리뷰 검색, 커뮤니티 | 긍정 평판? 부정 정보? |
| **5. 재구매/추천** | "다른 사람에게 추천" | AI가 경험 기반 추천 | 블로그 후기 작성 | 추천 소스로 등장? |

**시스템 구현:**
- 각 여정 단계별 대표 질문 3개씩 (총 15개) 자동 생성
- 5대 AI + 검색에 동시 프로빙
- 여정 단계별 가시성 히트맵 생성 (녹/황/적)

**리포트 출력 예시:**
```
춤추는고래 — 구매 여정 AI·검색 가시성 맵

          ChatGPT  Claude  Gemini  Perplexity  네이버   구글
인지        ❌      ❌      ❌       ❌       ⚠️(3p)  ❌
탐색        ❌      ❌      ❌       ❌       ⚠️(5p)  ❌
비교        ❌      ❌      ❌       ❌       ❌       ❌
구매결정    ❌      ❌      ❌       ❌       ✅(리뷰) ❌
재구매      ❌      ❌      ❌       ❌       ⚠️(블로그) ❌

→ 진단: "완전 비가시 상태. 인지·탐색 단계부터 콘텐츠 구축 필요."
```

#### 📊 브랜드 4대 가치 측정 방법론

> 참조: [썸트렌드](https://some.co.kr/) — 키워드 중심 소셜 빅데이터 분석
> 원리: **"사람들이 이 브랜드를 어떻게 말하고 있는가?"**를 데이터로 측정한다.

**1️⃣ 인지도 (Awareness Score) — "알려져 있는가?"**

| 측정 소스 | 측정 방법 | 지표 |
|-----------|-----------|------|
| 소셜 언급량 | 브랜드명 키워드로 블로그·인스타·뉴스·커뮤니티 문서 수 집계 (최근 3개월) | 월평균 언급 건수 |
| 검색량 | 네이버 검색량 (DataLab API) + 구글 검색량 (Trends) | 월평균 검색량 |
| AI 인지 | 5대 AI에 "OO 알아?" 직접 질문 → 브랜드 설명 가능 여부 | AI 인지율 (0~100%) |
| 경쟁사 대비 | 동일 카테고리 경쟁사 3개의 언급량·검색량과 비교 | 상대적 점유율 (SOV) |

**산출:** `인지도 = (소셜SOV × 0.3) + (검색SOV × 0.3) + (AI인지율 × 0.4)`

**시스템 구현:**
- Naver Blog/Cafe Search API → 브랜드명 키워드 문서 수 집계
- Naver DataLab 검색어 트렌드 API → 월별 검색량 추이
- Quick Probe 결과에서 AI 인지율 산출
- 경쟁사 동일 쿼리 실행 → SOV(Share of Voice) 계산

---

**2️⃣ 호감도 (Favorability Score) — "좋게 말하는가?"**

| 측정 소스 | 측정 방법 | 지표 |
|-----------|-----------|------|
| 소셜 긍부정 | 브랜드명 언급 문서에서 긍정/부정/중립 감정 분류 | 긍정 비율 (%) |
| 연관어 감정 | 브랜드와 함께 출현하는 형용사·감정어 추출 → 긍/부정 분류 | 긍정 연관어 비율 |
| 리뷰 감정 | bg_pain_points의 감정 분석 결과 집계 | 긍정 페인포인트 비율 |
| 부정 이슈 | "불만", "실망", "환불", "안 좋아" 등 부정 키워드 동반출현 빈도 | 부정 이슈 건수 |

**산출:** `호감도 = (소셜긍정률 × 0.4) + (연관어긍정률 × 0.3) + (리뷰긍정률 × 0.3)`

**시스템 구현:**
- 크롤링된 리뷰/블로그 텍스트 → Claude 감정 분석 (이미 pain/run에서 emotion 추출)
- 연관어 추출: 브랜드명 포함 문서에서 형용사·부사 TF-IDF → Claude로 긍/부정 태깅
- bg_pain_points의 positive_points / negative_points 비율 집계

---

**3️⃣ 추천도 (Recommendation Score) — "남에게 추천하는가?"**

| 측정 소스 | 측정 방법 | 지표 |
|-----------|-----------|------|
| AI 추천률 | 5대 AI 프로빙 결과에서 브랜드 언급 비율 | Gravity Score의 Mention Rate |
| 소셜 추천 키워드 | "추천", "강추", "최고", "인생템" 등 추천 키워드와 동반출현 빈도 | 추천 동반출현률 |
| 리뷰 추천 | 리뷰에서 "추천합니다", "재구매 의사", "주변에 권하고" 등 추출 | 추천 언급 비율 |
| 경쟁사 대비 | 경쟁사의 추천 키워드 동반출현률과 비교 | 상대적 추천 우위 |

**산출:** `추천도 = (AI추천률 × 0.4) + (소셜추천률 × 0.3) + (리뷰추천률 × 0.3)`

**시스템 구현:**
- AI 추천률: 이미 probe/run에서 측정 (brand_mentioned)
- 소셜 추천: 블로그/카페 검색에서 "브랜드명 + 추천" 동반 검색 → 건수 / 전체 언급 건수
- 리뷰 추천: bg_pain_points에서 extracted_question 중 "추천" 관련 + positive_points 내 "추천" 키워드

---

**4️⃣ 만족도 (Satisfaction Score) — "쓰고 나서 만족하는가?"**

| 측정 소스 | 측정 방법 | 지표 |
|-----------|-----------|------|
| 리뷰 평점 | bg_pain_sources의 rating 분포 (1~5) | 평균 평점 |
| 재구매 키워드 | "재구매", "또 살", "계속 쓰고", "n년째" 등 동반출현 | 재구매 의향률 |
| 불만 비율 | 부정 리뷰 중 제품 본질 불만 vs 부수적 불만 구분 | 핵심 불만률 |
| NPS 추정 | (추천 언급 비율) - (비추천 언급 비율) | 추정 NPS |

**산출:** `만족도 = (평점정규화 × 0.3) + (재구매율 × 0.3) + ((100-핵심불만률) × 0.2) + (NPS정규화 × 0.2)`

**시스템 구현:**
- 리뷰 평점: bg_pain_sources.rating 평균 → 5점 만점을 100점 스케일로 변환
- 재구매 키워드: pain/run 분류 시 "재구매" 관련 키워드 카운트
- 불만 분석: bg_pain_points.negative_points 중 핵심 불만(제품결함) vs 부수 불만(배송/포장) 분류
- NPS 추정: (추천 리뷰 비율) - (비추천/불만 리뷰 비율) → -100~+100 스케일

**그래비티 에이전트 역할:**

| 기능 | 설명 | 트리거 |
|------|------|--------|
| 신청 알림 | 새 `bg_apply_requests` INSERT 시 텐원에게 메시지 | DB webhook |

| 파이프라인 상태 보고 | 각 단계 완료/실패 시 메신저로 알림 | 파이프라인 실행 중 |
| 리포트 완료 알림 | 전체 분석 완료 시 리포트 링크와 함께 알림 | gap/run 완료 |

| 질문 응답 | 텐원이 "춤추는고래 점수 알려줘" 등 질문 시 즉시 응답 | 메신저 대화 |

**can_invoke 호출 관계:**
```
열시일분 ←→ 그래비티 ←→ 스마커
                ↕
            Whole See (트렌드 데이터 참조)
```
- 열시일분이 "춤추는고래 분석해" → 그래비티 호출
- 그래비티가 스마커에게 "마케팅 캠페인 데이터 줘" 요청 가능
- 그래비티가 Whole See에게 "업계 트렌드 줘" 요청 가능

- **점수 트렌드 차트** — 시계열 Gravity Score 변화 그래프
- **그래비티 에이전트 로그** — 이 제품 관련 에이전트 메시지 타임라인

#### 3) 사전 질문서 페이지 (신규: `/intra/gravity/[productId]/intake`)

- A~E 섹션 질문서를 웹 폼으로 구현
- 클라이언트에게 공유 가능한 외부 URL 생성 (`/brandgravity/intake/[token]`)
- 클라이언트가 작성하면 DB 저장 → 그래비티 에이전트가 알림
