안녕하세요, 시스템 아키텍트를 맡고 있는 안티그래비티입니다.
텐원 유니버스는 20개가 넘는 브랜드가 유기적으로 맞물려 돌아가는 거대한 모노레포(Monorepo) 플랫폼입니다. 저희 팀이 '보안, 체계, 안전성, 확장성'을 놓치지 않고 안정적으로 스케일업하기 위해, 앞으로 코드를 전개하실 때 상호 참고하고 논의할 수 있는 주요 목표와 아키텍처 가이드라인을 정리해 공유드립니다.

---

## 🎯 Current Priorities (현재 주력 과제)

### [Priority 1] 3계층 신원 아키텍처의 프론트엔드 연결 (진행 중)
* **제언:** 기존 인증 코드가 정상 작동할 수 있도록 하위 호환성을 유지하면서, Phase 2 (`identity-context.tsx` 생성 및 `auth-context.tsx` 어댑터 연결) 연동을 우선적으로 진행해 주시길 부탁드립니다.
* DB 엔진(Phase 1)은 원활히 가동 확인되었으니 편안하게 브릿지 연결 로직에 집중하시면 됩니다.

### [Priority 2] 모노레포 모듈화 및 폴더 분리 (차기 과제)
* **제언:** 공용 컴포넌트(`components/ui`)와 20개 브랜드별 특화 컴포넌트(`features/[brand]`)가 섞이지 않도록 폴더 분리 및 디자인 시스템 격리 방안을 모색 부탁드립니다. 각 브랜드 간의 상호 간섭(Side-effect)을 최소화하기 위함입니다.

### [Priority 3] 100만 트래픽 하이브리드 캐싱 (중장기)
* 마케팅 소개 페이지는 정적 캐싱(SSG/ISR)을 활용하고, 실시간 반응이 중요한 마이버스나 관리자 페이지는 SSR을 타도록 트래픽 분산 설계를 염두에 두시면 아키텍처가 더욱 단단해질 것입니다.

## 📘 Architecture Guidelines (설계 참고/조언 사항)

### 1. 공용 코어(Common Core) 확장과 폴더 분리의 기준점
유니버스의 장기적인 안정성을 유지하기 위해 공용 인프라와 개별 브랜드 영역의 역할을 분리하는 기조를 제안합니다.
* **✅ 어댑터 확장의 영역:** 현재 진행하시는 [Priority 1] 에서는 `auth-context.tsx`를 수정하여 신규 데이터를 표준 규격으로 변환(Adapter)해 주는 통합 작업이 필수적이므로 자유롭게 전개해 주십시오.
* **✅ 브랜드별 격리의 영역:** 반면, 특정 사이트(예: 바닥, 스마컴)에만 귀속되는 특수 요구사항이 생길 경우, 공용 코드(`auth-context.tsx`, `middleware.ts` 등) 내부에 `if (brand === 'badak')` 조건문으로 분기하기보다는, 해당 브랜드의 독립된 폴더(`features/[brand]`)에서 파생 컴포넌트를 만들어 해결하는 방식을 지향합니다.

### 2. 프리뷰 환경 최적화 (포트 충돌 방지)
로컬에서 `npm run dev` 테스트 중 간헐적으로 서버가 종료되는 현상을 겪으실 수 있습니다.
* **조언:** 이는 코드 문법 오류보다는 백그라운드에 남아있는 이전 프로세스가 포트(3000번)를 점유하고 있을 확률이 매우 큽니다. 불필요한 에러 디버깅에 시간을 낭비하시기보다, 프로세스를 깔끔히 종료하시거나 `npm run dev -p 4000` 처럼 다른 대체 포트를 띄워서 쾌적한 개발 리듬을 유지하시길 권장합니다.

### 3. API 페이로드 검증(Validation) 규칙
* 개발 테스트 중 400 Bad Request(`app/api/board/posts/route.ts` 등)를 만나게 되신다면, 백엔드의 치명적 에러라기보다는 필수 데이터(`site`, `board`, `title`, `content` 등) 누락으로 인한 입구컷(Validation) 방어일 가능성이 높습니다.
* API 연동 시 명세에 따른 필수 파라미터의 누락 여부를 함께 체크해 보시면 한층 매끄러운 진행이 될 것입니다.

### 4. RLS 보안 및 중앙 모니터링 고려
* 신규 API를 설계하실 때는 데이터 무결성과 접근 권한 보호를 위한 RLS(Row Level Security) 정책 방어를 기본값으로 고려해 주십시오.
* 나아가 전체 시스템의 장애를 파악할 수 있는 관제 시스템(Sentry 등) 확장을 위한 에러 로깅 문구도 남겨주시면 유지보수에 매우 큰 힘이 되겠습니다.
