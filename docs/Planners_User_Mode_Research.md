# Planner's Planner AI — 사용자 모드 연구
> 작성: 2026-04-28 | 목적: 중심 축 타겟별 차별화 설계 기반

---

## 1. 왜 "모드"인가 — 설계 배경

PP AI는 연간·월간·주간·일간이 연결된 구조를 가졌다.
하지만 **사람마다 일상에서 플래너를 쓰는 이유가 다르다.**

일정이 촘촘한 사람은 캘린더처럼 쓰고,
생각이 많은 사람은 노트처럼 쓰고,
아이디어가 넘치는 사람은 스케치북처럼 쓴다.

같은 화면을 보여줘도 **어디에 눈이 먼저 가는가**가 사용자 유형을 결정한다.
그 중심 축에 맞게 UI·AI 제안·기본값이 달라져야 한다.

---

## 2. 5가지 사용자 모드

### Mode 1. 스케줄 중심 — "시간표 인간"

> "오늘 몇 시에 뭐 해야 해?" 가 하루를 시작하는 첫 질문인 사람

**특징**
- 캘린더 블록이 핵심. 텍스트보다 시간 시각화가 먼저.
- 일정이 비면 불안함. 빈 칸을 채우고 싶어함.
- 시간 단위 관리 (15분·30분 단위) 선호.
- 반복 일정·리마인더 의존도 높음.

**대표 타겟**
- 미팅이 하루 3회 이상인 직장인·프리랜서
- 강의·수업 일정이 고정된 학생
- 광고 AE, 콘텐츠 PD처럼 외부 약속 중심 업무자

**PP에서 중심 축**
- Daily → 시간 블록 타임라인 뷰가 기본
- Weekly → 캘린더 엔트리 섹션이 Task보다 크게
- AI 제안: "내일 오전 10시 빈 블록에 X 넣는 건 어때요?"

**현재 PP 갭**
- 시간 블록 드래그 편집 없음
- 캘린더 엔트리와 Task가 시각적으로 동등 — 스케줄 중심 사용자에게는 Task가 노이즈

---

### Mode 2. 메모·노트 중심 — "기록 수집가"

> "생각나는 거 다 적어두면 나중에 쓸 데 있더라" 는 사람

**특징**
- 빈 텍스트 영역이 핵심. 구조보다 빠른 캡처.
- 키워드·단상·아이디어를 체계 없이 일단 저장.
- 나중에 연결되는 인사이트를 즐김.
- 태그·검색·링크로 노트를 구조화하는 편.

**대표 타겟**
- 작가·블로거·뉴스레터 발행자
- 연구자·기획자 (인풋이 많은 직무)
- Notion/Obsidian 헤비유저 중 "일정도 같이 관리하고 싶은" 사람

**PP에서 중심 축**
- Daily → Cornell Note(코넬 노트) 영역이 최우선
- Weekly → 메모 섹션이 Task보다 넓게
- Yearly → 연간 Theme(슬로건)과 Reflection이 핵심
- AI 제안: "이번 주 메모에서 반복된 키워드: '브랜드 정체성', '경쟁사 분석'. 프로젝트 브리프로 묶을까요?"

**현재 PP 갭**
- Daily 코넬 노트가 있지만 Weekly에서는 메모 영역이 작음
- 메모 간 연결(백링크·태그) 없음
- 검색 기능 없음

---

### Mode 3. 그림·아이디어 중심 — "비주얼 씽커"

> "말보다 그림이 빠르고, 직선보다 낙서가 생각을 더 잘 표현한다" 는 사람

**특징**
- 텍스트 입력보다 손그림·스케치·마인드맵 선호.
- 아이디어 발산→수렴의 사이클이 짧음.
- 무드보드·참고 이미지 링크를 많이 모음.
- 구조화된 폼 양식을 싫어함. 자유도가 핵심.

**대표 타겟**
- 크리에이티브 디렉터, 브랜드 기획자
- UX 디자이너, 일러스트레이터
- 아이디어 단계에서 메모가 폭발하는 스타트업 창업자

**PP에서 중심 축**
- Monthly → 무드보드·비주얼 키워드 입력 공간
- Yearly Vrief → 비주얼 무드 섹션 (이미지 첨부, 레퍼런스 URL)
- AI 제안: "이번 달 키워드 3개를 무드보드로 구성해볼까요?"

**현재 PP 갭**
- 이미지 첨부 기능 전혀 없음
- 자유 드로잉 캔버스 없음 (Apple Pencil 연동 등)
- 무드보드 영역이 설계되지 않음

---

### Mode 4. PP 꼼꼼 활용형 — "시스템 마니아"

> "플래너는 전략적으로 써야 한다. 연간-월간-주간-일간이 다 연결돼야 의미 있다" 는 사람

**특징**
- PP의 전체 구조를 처음부터 끝까지 채움.
- Yearly Vrief → Monthly → Weekly → Daily 흐름을 의도적으로 연결.
- OKR·GPR·회고 등 체계적 성과 관리 개념에 익숙.
- 기능 설명보다 사용 철학에 공감.

**대표 타겟**
- 자기 계발·생산성 마니아 (Notion 파워유저, GTD 실천자)
- 스타트업 팀장·PM
- 코칭·컨설팅 업계 종사자

**PP에서 중심 축**
- Yearly → Monthly → Weekly → Daily 전체 흐름을 한 화면에서 확인
- AI 제안: "월간 목표 3개 중 2번이 주간 계획에 반영 안 됐어요. 이번 주에 넣어볼까요?"
- 리뷰·회고 기능 강조

**현재 PP 갭**
- 연간 목표 ↔ 주간 계획 연결 가시화 없음
- 월간 GPR이 Weekly에서 진행률로 보이지 않음
- 회고(Reflection) 작성 유도 UI 약함

---

### Mode 5. 학생·직장인 입문형 — "처음 써보는 플래너"

> "플래너 쓰고 싶은데 어떻게 써야 할지 모르겠다" 는 사람

**특징**
- 빈 화면 앞에서 막막함을 느낌.
- 처음 1~2주가 지속 여부를 결정.
- 간단한 할 일 목록에서 시작, 점진적 확장 선호.
- AI가 먼저 질문해주면 쉽게 시작함.

**대표 타겟**
- 취업 준비생·대학생
- 플래너 입문 직장인 (20대 후반~30대 초반)
- 신년 계획 세우고 포기 반복한 사람

**PP에서 중심 축**
- 온보딩 → 3분 안에 첫 목표 1개 + 오늘 할 일 1개 완성
- Daily → 할 일 체크리스트 단순 뷰
- AI 제안: "오늘 어떤 하루였나요? 한 줄만 써볼까요?" (저항 최소화)

**현재 PP 갭**
- 온보딩이 단계별 안내 없이 빈 화면으로 시작
- 초기 템플릿 제안 없음
- 입문자를 위한 "오늘만 집중" 미니 뷰 없음

## 3. 모드별 핵심 비교표

| 항목 | Mode 1 스케줄 | Mode 2 메모 | Mode 3 비주얼 | Mode 4 시스템 | Mode 5 입문 |
|------|-------------|-----------|-------------|-------------|-----------|
| **첫 화면** | Daily 타임라인 | Daily 노트 | Monthly 무드보드 | Yearly 대시보드 | Daily 체크리스트 |
| **AI 역할** | 일정 제안·리마인더 | 키워드 연결·요약 | 무드보드 생성 | 목표 정렬 점검 | 시작 유도·칭찬 |
| **핵심 기능** | 캘린더 블록 편집 | 검색·태그·백링크 | 이미지 첨부·드로잉 | 전체 흐름 연결 | 온보딩·템플릿 |
| **빈 공간 반응** | 채우고 싶다 | 자유롭다 | 그리고 싶다 | 채워야 한다 | 막막하다 |
| **타겟 직군** | AE·PD·미팅 많은 직장인 | 기획자·작가·연구자 | CD·디자이너·창업자 | PM·코치·파워유저 | 학생·플래너 입문자 |

## 4. 구현 방향 제안

### 단기 (3개월 내)
1. **온보딩 모드 선택** — 가입 후 5가지 카드 중 선택 → 기본 뷰 자동 설정
2. **Mode 5 (입문) 온보딩 강화** — 3분 완성 가이드, 첫 목표 AI 추출
3. **Mode 4 (시스템)** — Yearly→Weekly 목표 연결 가시화 (먼저 구현됨, 강조 필요)

### 중기 (6개월)
4. **Mode 1 (스케줄)** — Daily 타임 블록 시각화 (드래그 편집)
5. **Mode 2 (메모)** — Weekly 메모 영역 확장 + 키워드 추출 AI
6. **모드 전환 허용** — 설정에서 "내 중심 축 변경" (모드는 고정이 아님)

### 장기 (12개월)
7. **Mode 3 (비주얼)** — 이미지 첨부, 무드보드, Apple Pencil/Stylus 지원
8. **모드 믹스** — 사용 패턴 AI 분석 → "당신은 Mode 2+4 혼합형이에요"

---

## 5. 설계 원칙

1. **모드는 라벨이 아니라 기본값이다** — 모드 선택 = 기본 뷰·AI 제안·빈 화면 안내가 바뀌는 것
2. **모드는 잠금이 아니다** — 언제든 다른 기능을 쓸 수 있다. 중심 축만 다를 뿐.
3. **AI는 모드에 맞게 말한다** — Mode 5에게 GPR 질문하지 않는다. Mode 1에게 무드보드 권하지 않는다.
4. **빈 화면의 적** — 각 모드의 "첫 시작" 경험을 가장 먼저 설계한다.
